# CrudForm

Formularz sterowany listą pól: sam obsługuje walidację po stronie klienta, błędy serwera, stan oczekiwania oraz skróty klawiszowe.

## Kiedy użyć

- Prosty formularz admina z polami tekstowymi: `text`, `email`, `password` lub `textarea` (tylko te cztery typy).
- Gdy walidacja to wspólny schemat Zod z `core` (przekaż go w `validate`), a zapis idzie przez `apiCall` do trasy API.
- Gdy chcesz mieć jednakowe zachowanie na każdym formularzu: błędy przy polach, blokada podwójnego wysłania, `Cmd/Ctrl+Enter`, `Escape`.

## Kiedy nie użyć

- Formularz z `Select`, `Checkbox`, polami zależnymi od siebie, wieloetapowy lub z własnym układem — złóż go z `Label`, `Input`, `Select`, `Checkbox` i `Button`.
- Decyzja z wyborem akcji i uzasadnieniem (karta decyzji w `/admin/returns/[id]`) — tam akcje mają różne skutki, użyj osobnych `Button` w `Card`.
- Strony publiczne (klient): używaj `Field`, `TextInput`, `Textarea`, `ActionButton`.
- Potwierdzenie czynności nieodwracalnej — `Dialog`.

## Jak złożyć

`CrudForm` sam niczego nie pobiera ani nie wysyła — robi to Twój `onSubmit`. Jedyne dozwolone miejsce wywołań `/api/*` to `apiCall` z `@easyrms/ui/api`. Błędy walidacji serwera zwróć jako mapę `nazwaPola: komunikat` (klucz `form` oznacza błąd ogólny).

```tsx
"use client";

import { apiCall } from "@easyrms/ui/api";
import { Card, CardContent, CardHeader, CardTitle, CrudForm, type CrudFormField } from "@easyrms/ui/admin";

const fields: CrudFormField[] = [
  { name: "orderNumber", label: copy.orderNumber },
  { name: "customerEmail", label: copy.email, type: "email" },
  { name: "reason", label: copy.reason, type: "textarea" },
];

<Card>
  <CardHeader>
    <CardTitle>{copy.title}</CardTitle>
  </CardHeader>
  <CardContent>
    <CrudForm
      fields={fields}
      validate={(values) => {
        const parsed = schema.safeParse(values);
        return parsed.success ? null : fieldErrorsFrom(parsed.error);
      }}
      onSubmit={async (values) => {
        const result = await apiCall("/api/returns", { method: "POST", body: values });
        return result.ok ? null : { form: result.error.message, ...result.error.fieldErrors };
      }}
      onCancel={() => router.back()}
      submitLabel={copy.save}
    />
  </CardContent>
</Card>;
```

`fieldErrorsFrom` to pomocnik z `app` zamieniający błędy Zod na mapę pól (szkic). `apiCall` nigdy nie rzuca: rozgałęziaj po `result.ok`; `result.error.fieldErrors` to gotowa mapa pól. Zwróć `null` z `onSubmit` przy sukcesie — formularz zostanie wyczyszczony (`form.reset()`).

## Tokeny

Pola: `Label` + `Input` z `border-input`, `placeholder:text-muted-foreground`, pierścień fokusu `ring-[3px] ring-ring/35`. `textarea` używa własnej, tej samej klasy (4 wiersze). Błędy: `text-destructive` (przez `ErrorMessage`). Przyciski: `Button` `default` (zapis) i `outline` (anuluj). Odstępy `space-y-4`, `space-y-1`, `gap-2`.

## Stany

| Stan | Wygląd i zachowanie | Jak wywołać |
|---|---|---|
| default | Pola puste, przycisk zapisu aktywny. | Story `Default`. |
| błąd walidacji klienta | `ErrorMessage` pod polem; nic nie jest wysyłane, brak stanu pending. | `validate` zwraca mapę błędów (story `ClientValidation`: puste „Order number”). |
| pending | Przycisk zapisu `disabled` i etykieta `Saving…`; po zakończeniu wraca. | `onSubmit` zwraca obietnicę, która jeszcze się nie rozstrzygnęła. |
| błąd serwera | Błędy pod polami; klucz `form` jako ogólny błąd nad przyciskami. Pola nie są czyszczone. | `onSubmit` zwraca mapę błędów (story `ServerErrors`). |
| sukces | Błędy znikają, formularz jest czyszczony (`form.reset()`). | `onSubmit` zwraca `null`. |
| pole hasła | Pole zamaskowane; przycisk obok pokazuje jego treść i zmienia tekst na „ukryj”. Stan pokazania jest lokalny dla pola. | Story `PasswordField`, przycisk „Pokaż hasło”. |
| bez anulowania | Brak przycisku anuluj; `Escape` nic nie robi. | Brak `onCancel` (story `WithoutCancel`). |

Uwaga: formularz nie ma propu `disabled` ani stanu tylko-do-odczytu.

## Dostępność

- Przełącznik hasła to zwykły `Button` z tekstem (bez `aria-pressed`): czytnik odczytuje aktualną akcję („Pokaż hasło” lub „Ukryj hasło”). Ustaw `autoComplete`, żeby menedżery haseł działały.
- Każde pole ma `Label` powiązany przez `htmlFor`/`id` równe `name` pola — `name` musi być unikalne na stronie.
- Błędy są w `ErrorMessage` z `role="alert"` i ogłaszane po pojawieniu się. Pole nie dostaje jednak `aria-invalid` ani `aria-describedby`, więc powiązanie błędu z polem jest tylko wizualne i przez kolejność w DOM.
- Formularz ma `noValidate` — walidację przeglądarki zastępuje `validate`; bez niej błędy zwraca tylko serwer.
- Klawiatura: `Cmd/Ctrl+Enter` wywołuje `requestSubmit()` z dowolnego pola (także `textarea`, gdzie sam `Enter` wstawia nową linię); `Escape` wywołuje `onCancel` (tylko gdy jest ustawiony).
- Przycisk anuluj ma `type="button"`, więc nie wysyła formularza. Podczas pending blokowany jest tylko przycisk zapisu, ale `Cmd/Ctrl+Enter` nadal wywoła `requestSubmit` — `onSubmit` powinien być odporny na podwójne wywołanie.
- Fokus po błędzie nie jest przenoszony automatycznie na pierwsze błędne pole.

## API

<Controls of={CrudFormStories.Default} />

| Prop | Typ | Opis |
|---|---|---|
| `fields` | `CrudFormField[]` | Pola: `name`, `label`, opcjonalnie `type` (`text` domyślnie, `email`, `password`, `textarea`) i `autoComplete` (token HTML, np. `username`, `current-password`, `new-password`). Pole `password` dostaje przycisk pokaż/ukryj. |
| `validate` | `(values) => Record<string, string> or null` | Opcjonalna walidacja klienta. `null` oznacza poprawne wartości. |
| `onSubmit` | `(values) => Promise<Record<string, string> or null>` | Wymagany. Błędy serwera lub `null` przy sukcesie. |
| `onCancel` | `() => void` | Opcjonalny. Włącza przycisk anuluj i skrót `Escape`. |
| `submitLabel` | `string` | Domyślnie `Save`. |
| `pendingLabel` | `string` | Tekst przycisku zapisu w stanie pending. Domyślnie `Saving…`, więc przekaż polski. |
| `cancelLabel` | `string` | Tekst przycisku anuluj. Domyślnie `Cancel`, więc przekaż polski. |
| `showPasswordLabel` / `hidePasswordLabel` | `string` | Teksty przełącznika pól `password`. Domyślnie `Show password` / `Hide password`, więc przekaż polskie. |
