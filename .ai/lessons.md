(2) A request past `submitted` (including a complaint at `received`, and any return at `approved`) can no longer be rejected or cancelled through the API, and only `rejected`/`cancelled` release the unit, so seeded order lines are used up for good: QA cleanup sets the status in the local test database (`db_release_rma` in `.ai/qa/lib/common.sh`, user-approved exception). Existing data can hold a line too (RMA-2026-00001 holds PL-10003), so pick a free seeded order per scenario and check `GET /api/returns` first. (3) `<input type="date">` ignores `agent-browser fill`; set it with `eval` through the native value setter plus an `input` event. A Radix select popup hides the page from the accessibility tree while it animates out, so wait for `[role=listbox]` to disappear before the next click. (4) `/bin/sh` `echo` on macOS expands `\n` inside a JSON body and breaks parsing: use `printf '%s'`. (5) The agent login is throttled to 10 attempts a minute per IP, so log in through the API once per script and wait a minute between runs that hit it; `GET /api/returns/[id]` returns a list, and `GET /api/returns` needs no agent, so prove a session with a `PATCH` on an unknown id (404 active, 401 disabled). (6) Assert on page text (`innerText`), not the interactive snapshot, for headings and paragraphs, otherwise a "not shown" check passes vacuously. (7) The server-rendered login page shows its text before hydration finishes, so a script that fills the fields right after `wait --text` can find them empty or missing ("no field labelled Hasło"): `login_ui_as` in the lib retries the whole attempt up to three times. - **2026-10-25 — Complaints and vendor claims (four traps a green build hides).** (1) `agent-routes.coverage.test.ts` walks `packages/app/src/app` and fails for any new page or route that is not in its `PUBLIC_ROUTES` set unless it is agent-protected, so a new customer page (`/returns/complaint/new`) must be listed there and in `agent-routes.test.ts`, and a new agent API prefix (`/api/suppliers`, `/api/supplier-claims`) must be added to `isAgentProtectedPath`; `npm test` only catches it in the `core` suite, not in `typecheck`. (2) In the DB test harness `migrateDown(to)` rolls back to `to` exclusively (that migration stays applied), so to undo migration N pass the id of migration N-1; and `pg_class` is global across the throwaway schemas of other open test files, so assert on `to_regclass('name')` (resolved through the schema's `search_path`) instead of counting `pg_class` rows. (3) DST changes the expected instants of calendar-day arithmetic: 2026-10-25 is the day Warsaw leaves summer time, so a `+14 days` due date from 24 Oct 10:00Z lands at 11:00Z, and `2026-10-25T22:30Z` is still 25 Oct (23:30) in Warsaw. (4) A `MailPort` whose `send` returns normally proves nothing about delivery (the log adapter), so anything that must not pretend to have mailed (the supplier claim) checks `mailPort.delivers` and stores a `draft` until a real send succeeded; the QA check for such a flow is a local SMTP sink that records the message (a ~30-line socket server), not the log. Also: zsh does not word-split an unquoted `$c`, so a gate loop over command strings needs `eval "$c"`.

- **2026-10-24 — Agent login (hand-built auth, Next.js 16 dev traps).** (1) `instanceof AppError` is unreliable: the container is built once on `globalThis` by whichever route bundle runs first, so services throw errors of that bundle's copy of `@easyrms/core` and every other route's `apiHandler` answered an opaque 500 for a plain 403/404/409. Fix: `AppError` carries a `Symbol.for` brand and `apiHandler` uses `isAppError`; never add `instanceof` checks on core errors in `app`. (2) After editing `packages/core/src/http` (or a shared server component like the admin shell) `next dev` can keep serving the stale bundle, so a new guard looks absent and a new nav link missing: restart the dev server (`kill` the pids from `ps`; `pkill -f next` kills the calling shell, exit 144). A restart also resets the ephemeral dev session secret, so sign in again. (3) `node:crypto` scrypt with N=2^16 needs `maxmem` above the 32 MiB default (`128*N*r*2`), else it throws. (4) Proxy (`proxy.ts`) only checks the signature; the page and route re-check against the database, so a disabled agent's old cookie passes the proxy and is stopped one layer down (expected). (5) A guarded API needs the CSRF header `x-requested-with` in `curl` checks, otherwise every POST is 403 before authentication even runs.

- **2026-10-24 — Storybook MDX docs in `ui` (three traps a green build hides).** (1) MDX under `packages/ui` imports `@storybook/addon-docs/blocks`, installed only in `app`; adding it to `ui` too creates a second copy whose docs theme context is missing, so every `<Canvas>` crashes at runtime with "reading 'content'" while `storybook:build` stays green. (3) Backticks inside JSX string props are not parsed (`DoDont`, `Swatch` render them with `Inline`). Straight `"` inside a JSX string in MDX breaks the compile: use „ ” typographic quotes.

- **2026-10-24 — CSRF 403 behind chained proxies.** In a cloud sandbox the browser `Origin` is the public host, but the app sees `Host: localhost:3000` and `x-forwarded-host` of the inner proxy, so `EASYRMS_TRUST_PROXY=true` cannot help and every POST answers 403 `csrf_rejected`; `EASYRMS_ALLOWED_ORIGINS` (exact origins) is the fix. Next loads `.env*` only from `packages/app` (the server's cwd), so a root `.env` is silently ignored: put app variables in `packages/app/.env.local`. To see what a proxy really sends, log the rejected request's headers to a file (the dev server's stdout is a pipe) and have the user retry, rather than guessing; `pkill -f next` also kills the calling shell (exit 144), so run it in its own call.

- **2026-10-23 — Racing submits in real Postgres.** Eight concurrent portal submits for one line answer 201 plus a mix of 409 (lost the lock, in-lock re-check) and 400 `already_claimed` (arrived after the winner committed, caught by the pre-lock check), so an end-to-end race check must accept both and assert exactly one row; the deterministic 409 proof is the `db` test that pauses inside the lock. `pg_locks` shows the key as `objid = hashtext(key) & 0xffffffff` with `objsubid = 1`, which lets a test prove the lock key is the canonical order number.

- **2026-10-23 — Submit replay vs eligibility.** A retry of an already-inserted submit would fail the pre-lock eligibility check (its own request consumed the quantity, or the window closed since), so `ReturnService.submit` does a read-only `findByIdempotencyKey` before that check and only then relies on the in-lock lookup for racing retries. In flow tests, simulate "another request slips in between the pre-lock check and the lock" with an awaited hook at the start of the fake `withOrderLock`, not a fire-and-forget submit (that one races the lock and flips the winner).

- **2026-10-23 — Customer lookup budgets.** `unavailable` from the order port must consume no limiter budget, so the lookup counter is `check`ed before the port call and `hit` only after a `found`/`not_found` answer (the per-IP and failed-attempt budgets are checked, never pre-consumed). A fresh local DB needs `npm run db:migrate` before routes that read `return_requests` work (a missing table is an opaque 500 `42P01`).

- **2026-10-23 — Idempotency unique violation.** MikroORM's `UniqueConstraintViolationException` has no `constraint` property in this version; match the constraint name in `error.message` (pg: `duplicate key value violates unique constraint "<name>"`), so an RMA collision is not mislabelled as an idempotency conflict.

- **2026-10-23 — Case sample lab (Zod 4, formatting, tests).**
  - `ZodObject.shape[key]` is typed as the bare `$ZodType` in Zod 4, which has no `.safeParse`; use the top-level `safeParse(field, value)` import (here to test whether a column is optional).

- **2026-10-23 — Agent decision workflow (DB tests, MikroORM, Next, shadcn).**
  - `em.transactional(cb, options)` writes `ctx` (and `propagation`) into the `options` object it receives. A shared constant such as `const JOIN = { propagation: REQUIRED }` carries the first caller's transaction into every later call, and later calls fail with "Transaction is already rolled back". Build the options object fresh per call.
  - The MikroORM CLI loads every `.ts` in `packages/db/src/migrations` (`glob: "!(*.d).{js,ts}"`): a `*.test.ts` there made `npm run db:migrate` crash on `import "vitest"`. Keep tests outside that folder (`src/tests/`). The migrator also rewrites `.snapshot-<database>.json` for whatever database it runs against, so test harnesses must set `migrations.snapshot: false` (a first run overwrote the committed snapshot with a throwaway schema).
  - A per-test Postgres schema: `clientUrl` query parameters are ignored; pass `driverOptions: { options: "-c search_path=<schema>" }` (merged into the `pg` pool options) plus `schema` so unqualified names in raw SQL and migrations resolve inside it.
  - Next bundles `@easyrms/core` once per layer, so `error instanceof NotFoundError` is false for an error thrown through the container into a page. Match on `error.code` (see `admin/returns/[id]/page.tsx`).
  - `npx shadcn@latest add` resolves the `@easyrms/ui/lib/utils` alias wrongly: it writes `import { cn } from "cn"` and adds the npm package `cn` to `packages/ui`. After adding a component, point the import at `../lib/utils` and run `npm uninstall cn -w @easyrms/ui`.

- **2026-10-21 — `spawnSync("npm", …)` silently fails on Windows.** `npm` is `npm.cmd` there, and Node won't start a `.cmd` without a shell, so `stdout` is `undefined` (`scripts/audit.mjs` then crashed in `JSON.parse`). ## 2026-10-23 — DB migration tests must pin `migrateUp(target)` once a later migration exists

`migrateDown()` without `to` reverts only the latest migration. Tests of an earlier migration's `down` that call `migrateUp()` (all pending) start undoing the wrong one as soon as a newer migration lands. Always `migrateUp(MIGRATIONS.<that migration>)` in such tests.

## 2026-10-18 — Stray npm in an ancestor `node_modules/.bin` hijacks nested `npm` calls

npm puts every ancestor directory's `node_modules/.bin` on PATH while running a script. A home-folder `C:\Users\<user>\node_modules` that contained npm 6 (a transitive dependency) shadowed the real npm inside scripts. npm 6 ignores `-w`, so the root `db:migrate` (`npm run db:migrate -w @easyrms/db`) called itself recursively and spawned hundreds of processes. Symptom: `npm ERR! code ELIFECYCLE` (npm 6 output) and repeated `"@easyrms/db"` args. Fix: delete the stray shims (`node_modules/.bin/npm*`) above the repo. Also on Windows `spawnSync("npm", …)` fails without `shell: true` (`npm.cmd`).

## 2026-10-14 — `URL.pathname` is not a filesystem path; `gh label list` stops at 30

In a plain Node script, `new URL("..", import.meta.url).pathname` keeps percent-encoding, so a checkout under a path with a space (`My%20Projects`) breaks `spawn` cwd and `fs` calls — use `fileURLToPath`. Also `gh label list` returns only 30 labels by default: a missing-label check against it gave a false "label does not exist" for `risk-low`; pass `--limit 200`. `gh pr review --approve` fails on your own PR; post the verdict as a `--comment` review instead.

## 2026-10-13 — `makeCrudRoute` typing: infer present verbs from config keys, not per-operation generics

Per-operation generics (`TList extends (service: TService) => …`) fail with context-sensitive lambdas (`service => service.list()`): TS falls back to the default and the param becomes `any`. Keep `list`/`remove` plain-typed and infer the key set with `config: Config & { [P in K]: unknown }`. Also: `pkill -f "<pattern>"` inside a Bash command kills the shell running it (the pattern is in its own command line) — kill by PID instead. The `npm audit` baseline was already red (Next < 16.4.0, `braces`) before the gate was added; `braces` has no patched release, so the gate uses `scripts/audit.mjs` with an expiring `audit-allowlist.json` instead of bare `npm audit`.

## 2026-10-13 — Don't mark a spec "Implemented" until its app-side pieces exist

Three phase specs claimed "Implemented" while `packages/app` had no container, routes, Tailwind or pages and `ui` was empty. Verify each spec's Design bullets against the tree (and run the flow against a real DB) before changing status or moving it to `implemented/`.

## 2026-10-13 — `next build` fails with `NODE_ENV=development`; rm of node_modules breaks the live dev server

The sandbox shell sets `NODE_ENV=development`, which makes `next build` crash with `Cannot read properties of null (reading 'useContext')` on `/_global-error`. Build with `NODE_ENV=production`. Also, the preview dev server auto-restarts while `node_modules` is deleted for a reinstall and ends up wedged (500s); kill it and start `npm run dev` again afterwards. `mv`/`git mv` across top-level dirs fails here with "Invalid cross-device link" — use `cp -a` then `rm -rf`.
