# Design system with Storybook as the manual

Status: implemented 2026-10-24 (not yet merged). Known gaps found while documenting are listed on the Storybook page "Wprowadzenie/Znane luki"; fixing them is follow-up work.

## TLDR
`packages/ui` has 31 components and a story per component, but no *rules*: nothing says which component to pick, how to
compose a screen, which colour token carries a status, or what not to do. Status colours are hard-coded (`sky/amber/red`
in `Banner`, `Field`, `ChoiceGroup`, the public inputs), the public side has no button (two pages copy a raw class
string), and the admin side lacks `Alert`, `Select`, `Checkbox`, `Dialog`, `Tabs`, `Skeleton`, `Separator`, `Tooltip`.
This spec turns Storybook into the manual for three readers: a developer, an AI agent and a designer reviewing a screen.
Done = someone builds a new screen from the docs alone, without guessing.

## Decisions (owner, 2026-10-24)
| Id | Decision |
|---|---|
| D1 | Keep the neutral shadcn theme (`primary` stays grey). Add **semantic tokens** only: `success`, `warning`, `info` and subtle variants of each tone incl. `destructive`. No hard-coded `sky/amber/red/green` classes in `ui` or `app`. |
| D2 | Documentation is in **Polish**; component, prop and token names stay English. |
| D3 | Add the missing admin primitives through shadcn: `Alert`, `Select`, `Checkbox`, `Dialog`, `Tabs`, `Skeleton`, `Separator`, `Tooltip`; plus tonal `Badge` variants. Public side gets `ActionButton`/`ActionLink` (the one place the primary action class lives). |

## Information architecture (sidebar order)
1. **Wprowadzenie** – start here: the three reader paths, the decision flow "which component", the two surfaces
   (admin = shadcn, public = Tailwind), the 10 rules.
2. **Fundamenty** – Kolory i tokeny (live swatches, light/dark, contrast), Typografia, Odstępy/promienie/cienie,
   Tryb ciemny, Dostępność, Treści (copy rules, Polish formatting stays in `core`).
3. **Wzorce** – composed screens as stories: list screen, form/decision screen, public form, wizard, the state matrix
   (loading/empty/error/success/disabled), status → tone mapping, destructive confirmation.
4. **Dla agenta AI** – a rule list with greppable "use X, never Y" lines and the same file paths an agent can read
   without running Storybook (the MDX is plain text in the repo).
5. **Dla designera** – a compliance checklist for reviewing a screen against the system.
6. **Admin / Public / Shared** – one docs page per component (MDX, attached to its stories): when to use, when not to,
   composition, tokens, states, accessibility, do/don't, props.

Every component page has the same sections (generated by shared docs blocks in `ui/src/storybook/docs/`), so the reader
knows where to look. A script (`npm run docs:check`) fails when a component in `ui/src/{admin,public,}` has no docs page
or a docs page lacks a required section, so the manual cannot silently rot. It joins the validation gate.

## Code changes
- `ui/src/styles.css`: semantic tokens + `@theme inline` mappings, light and dark, AA contrast verified by script.
- `Badge` variants `success|warning|info`; `Button` destructive uses `destructive-foreground`.
- `Banner` (+`success` tone), `Field`, `ChoiceGroup`, public inputs, `admin/Alert`, `dev-samples`: tokens instead of raw colours.
- `app/admin/returns/status-badge.ts`: status → tonal variant (documented in the "Status → ton" pattern).
- `ActionButton`/`ActionLink` in `ui/src/public/`, used by `_lookup/lookup-form.tsx` and `returns/page.tsx`.
- AGENTS.md: a "Design system" rule pointing at the docs and the check; engineering standards §2 updated.

## Out of scope
Brand colours (teal from the concept mockup), white-label theming, visual regression tests, `addon-vitest` a11y gate,
Storybook MCP. Each is a later spec.

## Acceptance
- Every `ui` component has a docs page with all required sections; `npm run docs:check` is green.
- A new screen can be assembled from "Wzorce" + component pages; the "Dla agenta AI" page lists the allowed
  components and tokens.
- No raw colour classes remain in `ui`/`app` (grep gate in `docs:check`).
- `typecheck`, `lint`, `test`, `audit`, `storybook:build`, `build` green.
